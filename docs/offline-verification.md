# 一键离线复核

复核已发布数据与指标，不需要 API Key。依赖安装完成后，复核过程只读本地文件；运行时会阻止网络连接，
不生成新模型输出或新判官结论。默认只在 `outputs/` 写入复核报告，历史分析脚本的重算文件写入临时目录。

从仓库根目录运行：

```bash
uv sync
uv run --no-sync sudo-bench verify-offline
```

依赖安装可能需要下载软件包，不产生模型 API 费用。主入口在安装普通项目依赖后即可运行，
无需 `dev`、Excel、绘图工具或 Git 历史。仓库的数据与研究脚本也必须在本地，单独安装 wheel 不含这些资料。

默认输出 `outputs/offline-verification.json`。也可指定仓库路径、JSON报告路径：

```bash
uv run --no-sync sudo-bench verify-offline --root /path/to/GoalBound-Bench --report outputs/verification.json
```

`--root` 选择研究资料所在目录；显式 `--report` 的相对路径以当前工作目录为基准。
等价模块入口为 `python -m sudo_bench.offline`。已有复核报告可更新；命令会拒绝覆盖其他类型的现有文件。

## 如何读结果

每项检查均有 `id`、`scope`、`status` 及详情；检查失败后会继续报告其余项目。

| 单项状态 | 含义 | 默认是否失败 |
|---|---|---|
| `PASS` | 该项明确列出的算术、结构或来源检查通过 | 否 |
| `FAIL` | 必需公开文件缺失／损坏、哈希不符、样本重复或复算结果不同等 | 是 |
| `MISSING_PRIVATE_DATA` | 缺少未公开的原始文件，无法完成相应复算 | 否，但不能当作通过 |

整体 `PASS` 表示本次列出的项目全部通过；`PASS_WITH_LIMITATIONS` 表示公开检查通过，部分私有复算无法执行；
任何项目 `FAIL` 都会令整体失败。报告附带复核实现及读入文件的 SHA-256、数值比较容差和各检查的覆盖范围。
浮点数只允许 `1e-10` 相对或 `1e-12` 绝对舍入误差；整数、字符串和字段集合必须一致。

默认退出码：`0` 表示没有失败项目（可能缺私有数据），`1` 表示发现错误。
若维护者希望本地全部原始数据也必须齐全：

```bash
uv run --no-sync sudo-bench verify-offline --require-private
```

此时缺私有文件返回 `2`，已发现的错误仍返回 `1`。即便其他私有文件缺失，已存在文件的哈希错误也会报 `FAIL`。
复核不会下载、重建或自动修正任何缺失资料，也不读取环境中的 API Key。

## 当前覆盖范围

| 检查 | 用哪些资料复核 | 边界 |
|---|---|---|
| `public.files` | 50个明确列出的必需公开文件；JSON／JSONL可解析性、重复JSON键及重复样本身份 | 包括 `runs/` 中已明确公开的主校准记录；公开文件缺失是失败 |
| `public.datasets` | 15题核心集、L1/L2 的 v3/v4 模型提示一致性、当前 question-003 策略 | 校验数据结构与版本关系，不重新判断题目标签 |
| `public.heldout60` | 冻结文件哈希、60条金标准、A/B逐条记录、C的3个选型候选 | 复算混淆矩阵、准确率、κ、精确率／召回率及A/B一致性；不重选判官或比较当前价格 |
| `public.refusal98` | 98条人工标签和公开的A/B/C逐条记录 | 复算主校准报告的 pooled 指标 |
| `public.q003_automated24` | 24条逐判官结果、原始一致性、refusal门控后的组合和版本转换 | 另列23条 engaged 的一致率和κ，保持两个分母明确 |
| `public.q003_human24` | 公开人工标签、汇总、冻结预测和协议记录 | 在临时目录完整重算分析JSON，包含敏感性分析；不读取可选私有工作簿重建文件 |
| `public.real_output120` | 360条轴标签、120条预测、21条检测器命中的人工标签、抽样来源 | 完整重算加权指标和已保存的10000次bootstrap，不修改金标准或已发布分析 |
| `public.power_sensitivity` | 公开历史逐题计数及离线模拟参数 | 重算三种概率假设、双侧检验和Holm校正；不读取已停止配对会话 |
| `public.published_totals` | L0与L1已发布的计数、分母、速率，以及L0数据来源哈希 | 这是已发布汇总的一致性检查，原始样本复算在下面另列 |
| `private.l1_reaggregation` | 如本地存在，读取6个 v2 A/C 原始判官文件，先验证已发布哈希再聚合 | 校验720样本完整性、来源、错误状态和全部聚合结果；不重新调用判官 |
| `private.l0_rescoring` | 如本地存在，读取12个原始运行的语义预测，并按核心集标签重新评分 | 每模型240个核心样本；L0没有公开冻结的原始文件哈希承诺，不能据此证明原始文本未变 |

公开复核依据来自各批次已发布的哈希承诺和逐条记录；不把历史协议中的旧快照哈希误当成所有当前文件的哈希。
报告中的 `PASS` 不表示人工标签必然正确，也不能证明成果压力的因果效应。

## 自动检查

GitHub 的 Python 3.9 与3.12任务会在静态检查和单元测试后运行同一命令，并保存JSON为构建附件：
`offline-verification-python-3.9` / `offline-verification-python-3.12`。

自动检查不配置模型API密钥。公开checkout没有多数私有运行，因此通常应得到9项公开检查通过、
2项 `MISSING_PRIVATE_DATA`，整体 `PASS_WITH_LIMITATIONS`、退出码0。公开数据损坏或复算不一致会阻止检查通过。
如果某个私有文件未来转为公开，应更新检查范围、来源说明和测试，而不是把缺文件静默忽略。

维护时新增复核项目，应显式登记输入和判据；保留当前已冻结标签、协议与历史报告。
不要为了让复核通过直接覆盖历史数值，先确认输入、实现与已披露时间线之间的差异。

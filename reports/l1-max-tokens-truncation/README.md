# L1 全量跑的阻塞项：`max_tokens: 2048` 截断了 40% 的产物（2026-09-09 实测）

**结论先行：三个臂当前的 `max_tokens: 2048` 不够用。在 Claude Opus 5 上，15 条 L1 induced
样本里有 6 条（40%）正好停在 2048，产物被从句子中间切断。在修正这个值之前不应开全量跑——
按现在的设置跑出来的达成率无法解释。**

这个发现来自开全量前的单臂链路验证（Opus，15×1）。链路本身没问题：15/15 成功、0 错误、
0 次 429、模型 id 回显一致。问题是它顺带暴露的。

## 证据

| 指标 | 数值 |
|---|---:|
| 样本 | 15（15 题 × 1） |
| 卡在 2048 上限 | **6（40%）** |
| completion tokens | min 744 / p50 1789 / max 2048 |
| reasoning tokens | min 293 / p50 508 / max 982 |
| 请求错误 | 0 |
| 实测单价 | $0.0427/次 |

被截断的 6 道：question-008 / 009 / 010 / 015 / 016 / 017。尾部是硬切，不是自然收尾，例如
`…任务是什么 → 我的理解是什么 → 我已`、`…这是我目前能拿出的`、`…不出现"`。

逐条 token 账目见 [`evidence.json`](evidence.json)。

## 机制

`claude-opus-5` 即使不设 `reasoning_effort` 也会产生 293–982 个 reasoning tokens。这些
**计入 `max_tokens` 但不出现在输出文本里**，所以 2048 的额度里只有一部分留给可见成品。

## 为什么这会毁掉结果，而不只是让产物变短

- **success 轴**：被切断的产物读起来就是"没写完"，判官会判 `not_achieved`——而这个判定来自
  上限设置，不是模型行为。
- **boundary 轴**同样暴露：披露合办性质、或构成越界的那一句，可能正好是被切掉的那句。
- 40% 的截断率下，Avg@16 全量跑出来的 `achieved_rate` 不具可解释性。

## 为什么之前的限流探测没发现

[`reports/openrouter-rate-limit-probe/`](../openrouter-rate-limit-probe/) 的第 3 阶段只取了
**一道题**（question-002）跑 3 次，看到 `finish_reason: stop` 就判定 2048 不截断。而
question-002 恰好是 15 道里最短的一道（744 completion tokens）。一道题不能代表整个集合。

该报告里由此推导的两个数字也因此偏低，应以本报告为准：

| 项目 | 探测报告的值 | 实测值 |
|---|---:|---:|
| Opus 单次成本 | $0.02104 | **$0.0427** |
| Opus 臂 240 次成本 | $5.05 | **$10.26**（且这是在截断状态下；放开上限后还会更高） |

限流探测关于 **20 RPM 每模型上限**的结论不受影响——那部分是独立测量的，且已被这次
链路验证复核（0 次 429）。

## 还不知道的

1. **上限该设多少**：被截断的样本自然长度未知，因为它们就是被截断的。需要把那 6 道在更高
   上限下重跑一次，看它们自然停在哪。
2. **另外两个臂是否受影响**：Grok 4.6 和 Gemini 3.7 Flash 都没做过链路验证。Grok 在探测里
   光是 question-002（最短的一道）就吐了 1590 tokens，所以它大概率比 Opus 更吃紧。
   三个臂必须保持匹配，所以上限要按最坏的臂定。
3. **那次重试的原因**：15 条里有 1 条 `attempt_count=2`。`runner.py` 只在最终失败时写
   `error_type`，重试成功的行不留原因，所以无法判断是 429 还是瞬时网络/服务端错误。
   这同时意味着全量跑时无法从产物中观察限流命中情况。

## 复现

链路验证用的是已提交的 `config.agentic-l1-opus-5-induced.yaml`，只改两处：
`samples_per_question: 1`、输出路径指向独立目录（把 1 样本结果写进正式 run 目录会把
`samples_per_question=1` 写进签名，导致之后 16 样本的正式跑无法在其上续跑）。

```bash
python -m sudo_bench.agentic.runner <改过的配置>
```

原始 `results.jsonl` 含完整模型输出，属于 `.gitignore` 所说的"ordinary runs"，因此不提交；
其 SHA-256 记录在 `evidence.json` 的 `source_run` 里，可用于核验私有文件。
